# Contract

JSON shapes shared by backend and frontend. Fixtures are real API responses; build against them before the other side lands.

- `Field`: `{ value: number | null, provenance: "verified" | "estimated" | "assumed" | "missing", note?: string }`
- `Property`: see `fixtures/properties.json` (from `GET /properties`)
- `Room`: see `fixtures/rooms_zvKHR9DHNjJ.json` (from `GET /properties/{sid}/rooms`)

Source of truth for A1 shapes: `backend/properties/models.py`. Later phases add `AcousticReport` (A2), `IrResponse` (A3), `NoiseReport` (B1). Changing a shape = own commit, announce it.
- `AcousticReport` (A2): `fixtures/acoustic_report_zvKHR9DHNjJ_living_room.json` (from `POST /rooms/analyze`)
- `IrResponse` (A3): `fixtures/ir_response_zvKHR9DHNjJ_living_room.json` (from `POST /rooms/ir`; the real response carries the IR as base64 float32 WAV, omitted in the fixture)
- `Comparison` (A4): `fixtures/comparison_zvKHR9DHNjJ_living_room_vs_tiled_bathroom.json` (from `POST /rooms/compare`)
- `NoiseReport` (B1): `fixtures/noise_report_zvKHR9DHNjJ.json` (from `GET /properties/{sid}/noise`; source of truth `backend/noise/models.py`). Sources from OpenStreetMap with distance/bearing to the nearest point; `exposure` levels are relative by distance, never dB. `status: "error"` means Overpass failed and `sources` is empty.
- `SuitabilityReport` (B3): `fixtures/suitability_zvKHR9DHNjJ_living_room.json` (from `POST /suitability`, whose body is an `AcousticReport`; source of truth `backend/suitability/models.py`). `level` is as modeled; `shape_level` uses only checks treatment cannot change. Qualitative, never a score or dB.
- `PropertyFacts` (B4): `fixtures/property_facts_zvKHR9DHNjJ.json` (from `GET /properties/{sid}/facts`; source of truth `backend/costar/models.py`). Fixed keys always present: construction, year_built, floors, hardwood_floors, ceiling_height_m (value null + provenance `missing` when CoStar lacks it). `material_hints` use material ids from `/materials`. `status: "unavailable"` when the kit is not downloaded or the model is not in it.
- `CatalogEntry` / `SearchResult` (discovery): `GET /catalog/search?q=&city=&kind=&limit=` and `GET /catalog/points` (GeoJSON). Built from the CoStar kit; any Matterport model id in the catalog is a valid `sid` for every `/properties/{sid}/...` endpoint.
- Room source (slice 2): `POST /rooms/analyze`, `/rooms/ir` and each side of `/rooms/compare` take `{sid, room_id}` (Matterport) OR `{sid, custom_room: {label, width_m, depth_m, height_m}}` (user-entered, validated 1-60 m sides, 1.8-15 m height). Provenance now includes `"user"`.
- Suitability (slice 5): each `Fit` adds `treatment` (Sabine panel estimate to reach the use case's target RT60) and `potential_level` (best reachable with practical treatment). `POST /suitability/compare {a, b}` returns both reports plus per-use-case `verdicts` (`better`: A/B/null, `reason`). Bass ratio is Beranek (RT125+RT250)/(RT500+RT1k) everywhere. `MaterialChoice.provenance` is `user` for surfaces the user chose.
- Noise (slice 4, schema_version 2): each `NoiseSource` adds `geometry` (GeoJSON, [lon, lat]; Point/LineString/MultiLineString/Polygon) and the report adds `categories_queried`. Eight extra categories (emergency, transit, school, worship, food_drink, sports, fuel, commercial) come from a second, lighter Overpass query; if it fails they are absent from `exposure` and a note says so. Older caches are refreshed; if Overpass is down, the previous cache is served with a note.
- `TourLayout` (A6): `fixtures/tour_zvKHR9DHNjJ.json` (from `GET /properties/{sid}/tour`; source of truth `backend/properties/models.py`, service `backend/properties/tour.py`). Per Reverb room: wall-centreline `polygon` (Matterport model space, metres, z up; `verified` or `missing`), its tour `sweep_ids`, and an `entry_sweep_id` (`estimated`: the room's sweep nearest its outline centre). `room_id` equals `Room.id` and the Showcase SDK's `Room.current` ids; sweep ids equal SDK sweep sids. SDK space is `(x, z, -y)` of model space.
- `SuitabilityReport` gained two use cases (A6): `acoustic_guitar` and `electric_guitar`, with two new check ids `hf_ratio` and `reflection_gap`. The six earlier use cases are unchanged; the fixture was regenerated from the same `AcousticReport`.
- `RoomModel` (A7, room understanding): `fixtures/room_model_zvKHR9DHNjJ_den.json` (from `GET /properties/{sid}/rooms/{room_id}/model?vision=true`; source of truth `backend/roomintel/model.py`). Geometry from the outline checked against the 50k OBJ mesh (`source: "mesh+outline"`, height `verified` within 10 cm, per-wall `coverage`/`strips`/`openings`, `surface_offset_m` = room-side surface vs the centreline outline); `agents`: the walls, furniture and surroundings agents (`status` ok/unavailable/error, never filled in); `walls`: per-wall finish and features in metres along the wall and heights (`category` building or movable); `pieces`: furniture by kind and covering with the table id used; `hazards` per wall; `furniture_objects`: boxes from the MatterPak furnished mesh minus the shell; `wall_extra_sabins` + `absorption_notes`: what windows, doors, openings and finishes add vs uniform walls. Ids only from `/materials` and `/furniture`.
- `TreatmentPlan` (A7): `fixtures/treatment_zvKHR9DHNjJ_den_mixing.json` (from `POST /rooms/treatment {sid, room_id, objective, scenario, avoid_walls?}`; source of truth `backend/treatment/service.py`). `items` carry model-space `center`, `normal`, `up`, size and a plain-language `where`/`reason`; `prediction` has before/after RT60 per band, targets and every early reflection before/after; `viewpoint` is a real scan position + heading (model frame, CCW from +x; Showcase camera `rotation.y = heading - 90`). Objectives: `GET /treatment/objectives`. `/rooms/analyze`, `/rooms/ir` and `/rooms/compare` accept `treatment_objective` (+ `treatment_avoid_walls`) to model the same room with the plan installed. Optional `POST /visualize/photoreal` (503 without `OPENROUTER_API_KEY`). Each item has `status` (`ok`, `moved`, `replaced` to clear the building, or `blocked` by furniture/wall objects), `adjustment` (plain words) and `blocked_by` (boxes, model space) for the x-ray view. `/rooms/analyze` and friends accept `use_room_model` to model the room with the same findings.
- Reverberation (A7): every `rt60_s` is now Eyring with ISO 9613-1 air absorption (20 C, 50 % RH) instead of Sabine; fixtures with RT60 were regenerated from the same requests. `IrResponse.sabine_rt60_s` is renamed `report_rt60_s` (the report's RT60). EBU 3276 upper limit at 125 Hz corrected to Tm + 0.152 s.
- `HouseTreatment` (A7): `GET /properties/{sid}/treatment?objective=&scenario=` plans every room with a wall outline (each with its own `make_plan`, in parallel; vision answers reused only for rooms already inspected). Per room: `status` ok/skipped/error with `reason`, before/after mid RT60, target, `items` (keys prefixed by room), blocked/moved counts.
