# REVERB — project rules
Read PRD.md, CONTEXT.md, SLICES.md (phases), WORKFLOW.md (ownership, git, prompts) first.

## Commands
- Backend setup: `cd backend && python3 -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt`
- Backend run: `cd backend && uvicorn app.main:app --port 8000`
- Backend checks: `cd backend && ruff check . && ruff format . && pytest -q`
- Frontend: `cd frontend && npm install && npm run dev` (http://localhost:5173, proxies `/api` to :8000)
- Frontend checks: `cd frontend && npm run build && npm run lint && npm test`
- Matterport Bundle SDK (3D floor tints): `cd frontend && npm run setup:matterport` (copies the licensed showcase bundle into git-ignored `public/matterport-bundle/`; never commit it). Without it the tour falls back to the Embed SDK with no 3D tint.
- Vite proxy target: `REVERB_API=http://localhost:8010 npm run dev` when :8000 is taken.

## Rules
- Secrets live in `.env` at the repo root (git-ignored; never commit, never echo). `data/` and `backend/.cache/` are git-ignored.
- Acoustic numbers come only from deterministic Python. LLMs never produce measurements or dB values.
- Every input/output carries provenance: verified | estimated | assumed | missing. Never fill a gap silently.
- Modeled audio is labelled a modeled approximation, never measured.
- Shapes shared by backend and frontend live in `contract/` (fixtures are real API responses). Change them in their own commit and tell the other person.
- Discovery: `backend/catalog/` indexes every CoStar-kit property with a Matterport scan (~5,100; cached in `data/cache/catalog/index.json`, delete to rebuild). `shortlist.json` only marks DEMO picks. Routers check `properties.service.is_known(sid)`, not the shortlist.
- Matterport rooms may omit `dimensions` or any field in it. Use `.get`; never index.
- Matterport lat/long arrive as strings. maplibre-gl v6 has named exports only (no default import).
- If `npm install` fails with root-owned cache files: `npm install --cache <some writable dir>`.
- Write failing tests first for calculations and data transforms; run the real app before calling a phase done.
- Pyroomacoustics: seed with `pra.random.seed(n)` (not `np.random.seed`) or IRs are not reproducible. Pure-specular rays (scattering 0) give RT60 40-50% above Sabine; we assume scattering 0.5. Below ~250 Hz the IR is modal and will not match Sabine.
- Web Audio: set `ConvolverNode.normalize = false` BEFORE assigning `.buffer`. One source feeding both rooms' convolvers keeps A/B switching on one playhead.
- MapLibre: call `setWorkerUrl` with `maplibre-gl/dist/maplibre-gl-worker.mjs?url` (Vite moves the bundle, so the default worker URL 404s and tiles never render), and `map.resize()` on container resize.
- API tests run offline: `backend/tests/test_api.py` monkeypatches `properties.service.fetch_model` with a recorded Matterport response.
- Noise Scout (Deep Agents): needs `OPENROUTER_API_KEY` (preferred, uses `openrouter:anthropic/claude-sonnet-5.5` + `haiku-5.5`) or `ANTHROPIC_API_KEY` in `.env`; override with `NOISE_SCOUT_MODEL` / `NOISE_SCOUT_SUBAGENT_MODEL`. A $0-limit OpenRouter key only runs `:free` models; tested working: coordinator `openrouter:nvidia/nemotron-3-ultra-550b-a55b:free`, specialists `openrouter:nvidia/nemotron-3.5-super-vl:free` (~5 min per run; results cached in `data/cache/noise_scout/`). The LLM never supplies facts: findings must cite OSM ids returned by tools in that run, and dB claims are rejected (`noise_scout/validate.py`).
- Noise map: one MapLibre map (`features/map/PropertyMap.tsx` + `noiseLayers.ts`) draws properties and noise geometry; there is no separate noise map. Public Overpass is often slow or down: `noise/service.py` splits base/extra queries, tries 4 mirrors, and serves the last good cache on failure. Bump `SCHEMA_VERSION` when the report shape changes.
- UI is one five-step cycle (`frontend/src/ui/steps.ts` + `ui/journey.tsx`): Find a place → Choose a room → Treatment plan → Listen → Verdict. `App.tsx` gates each step (Next stays off until it has what it needs). Keep each step to its essentials; detail goes behind `<details>`. The 3D tour opens over the steps (they stay mounted, so a loaded recording survives) and hands a room back via "Use as Room A/B". "Hear the room before and after" puts Room A treated (`MaterialSelection.treatment`) in slot B.
- Noise location: Matterport geolocation (verified), else the CoStar record's coordinates (estimated, with a note) in `noise/router.py`, so a property without a usable scan still gets surroundings.
- Scan availability: `GET /properties/{sid}/viewer` (`properties/viewer.py`) checks visibility/state/publication via the Model API (cached in `backend/.cache/matterport/viewer/`); a 300-scan random sample of the catalog was 100% embeddable.
- Matterport 3D tour (A6): the browser gets only `MATTERPORT_SDK_KEY` (domain-restricted; injected by `vite.config.ts`). Model API key/token stay server-side. Model API positions are z-up; SDK/three.js is y-up: sdk `(x, y, z)` = model `(x, z, -y)` (verified on zvKHR9DHNjJ).
- SDK `Room.current` follows the camera, so during a fly-through it reports every room on the path; only trust it once `Sweep.current.sid` is non-empty. `Sweep.current.roomInfo` was wrong on zvKHR9DHNjJ; use `Room.current` or the Model API sweep->room map.
- Self-hosted bundle 26.5.4 stays in `appphase.loading` with its loading screen up although the view works; `revealBundleView` hides `#loading-gui` once the SDK reports a mode. Do not assign the iframe `src` twice (React StrictMode) or the Embed showcase can stay black.
- Navigation: one step open at a time (`active` in `App.tsx`), clickable stepper, and `StepNav` (Back/Next) whose `need` text says what blocks Next. The 3D tour is a separate view opened from Explore (tour) or Analyze/Decide (heatmap) with a Back button.
- Furniture: Matterport `objectAnnotations` is empty for the kit's scans, so furniture is a typical set per room type (assumed) or user-edited (`acoustics/furniture.py`). All room requests go through `roomBody()` in `roomRef.ts` (furnished + wall area from the outline); a slot's furniture edits ride inside its `MaterialSelection` as `furniture`.
- Acoustic heatmap: `acoustics/field.py` (C50, early wall reflections within 5 ms, 30-200 Hz bass unevenness) + `advice.py`; `GET /properties/{sid}/insights`. Frontend `features/heatmap/`: `buildFieldMesh` (SDK space), Bundle Scene overlay drawn without depth test (so it is hidden while the camera is inside a room), 2D `FieldPlan` fallback.
- Noise risk: `noise/risk.py` (assumed category intensity x proximity, heat points along OSM geometry), `GET /properties/{sid}/noise-risk`, MapLibre heatmap layer. Noise Scout's `get_risk_ranking` tool makes the agents research the top-ranked sources; findings attach to risk rows by cited OSM id.
- Music room flow (tour): tour first; "Choose my music room" switches to the top-down view (wait for the fly-in to settle, or Matterport throws ViewmodeActiveTransition); the clicked room alone gets the field heatmap, then "Analyze and listen as Room A/B" puts it in the journey. Room tints are hidden while choosing so the plan stays clean.
- Matterport room ids repeat across models (they are per-model); always key rooms by (sid, room_id).
- IR: `ir/service.effective_alphas` scales the shoebox's surface absorption to the report's total, so furniture and outline wall area reach the audio (before this the furnished IR decayed like an empty box).
- Demo: `shortlist.json` `demo_pair` (good: zvKHR9DHNjJ 40 m3 living room; bad: iUcvMLNZUY1 188 m3 kitchen on Sunset Blvd), served by `GET /demo`; Decide shows `HouseVerdict` cards (rules in `features/decide/verdict.ts`); the player adds illustrative outside noise from each house's risk ranking (`features/audio/ambience.ts`).
- Room understanding (`backend/roomintel/`): LangGraph pipeline geometry → imagery → vision → assemble. Matterport Model API gives `assets.meshes` 50k/500k OBJ (`defurnished_*.obj`, same z-up frame as room polygons), 2k skyboxes per `panoLocations` entry (6 faces: 0 up, 1-4 sides, 5 down) and `bundle(id:"mp:matterpak")` (unlocked on the kit models; not downloaded). Signed asset URLs expire (HTTP 410): `fetch_assets(sid, fresh=True)` and retry.
- Skybox orientation (verified on zvKHR9DHNjJ by projecting room corners): face 1 looks along the pano rotation's yaw (CCW from +x), faces 2-4 turn clockwise 90° each; `roomintel/panorama.py` has project/floor_point. Brightness does not reliably find windows (blinds, art, white doors); windows come from the vision agent or the user's "keep this wall clear".
- Vision agents (`roomintel/agents.py`, run in parallel by the LangGraph pipeline in `roomintel/model.py`): walls (one rendered view per wall from `roomintel/views.py`, features as image rectangles converted to metres/heights in `merge.py`), furniture (kind + covering: leather vs fabric), surroundings (in-room hazards). Need `OPENROUTER_API_KEY` (or `ANTHROPIC_API_KEY`); `REVERB_VISION_MODEL` overrides. The current key has a $0 limit, so `.env` sets `openrouter:nvidia/nemotron-3.5-super-vl:free` (~25-85 s per agent). Answers are plain JSON parsed + pydantic-validated with one retry; cached in `data/cache/vision/` per agent (bump `PROMPT_VERSION` when a prompt changes). Ids only from `MATERIALS`/`FURNITURE`; blinds are not curtains; without a key everything stays `assumed`.
- Treatment engine (`backend/treatment/`): products and coefficients only from `acoustics/products.py`; positions only from `placement.py` (image sources, corners, mesh openings); `optimizer.py` enumerates configurations against `objectives.py` targets (EBU Tech 3276 for mixing/critical). No LLM touches a number, position or recommendation.
- Treatment preview: `Renderer.takeScreenShot` omits custom Scene objects; `features/treatment/scene.ts` renders with the component context's renderer/scene/camera and reads the canvas in the same call (set `objectRoot.visible` directly; input changes apply on the next SDK tick). Showcase camera `rotation.y = model heading - 90` (verified).
- Furniture geometry: the MatterPak zip is fetched member-by-member with HTTP range requests (`properties/matterport.furnished_mesh_path`, ~7 MB of a 138 MB zip); furnished points > 7 cm from the defurnished shell are furniture, grouped on a 10 cm voxel grid (`roomintel/obstacles.py`). Flat art is too thin to see there; the walls agent reports it.
- Treatment fitting (`treatment/fit.py`): building conflicts (shell points in the item, < 90% wall behind it, agent windows/doors/radiators, mesh openings) -> move within limits that keep the item's job (a first-reflection panel must still cover its point), else replace (landscape, half-size panel, half-height trap), else drop with a note. Furniture/wall objects -> try other spots first, then lift above the furniture, else `status: "blocked"` with `blocked_by`; the 3D preview draws those see-through (depth test off, orange edges) with the blockers as red boxes.
